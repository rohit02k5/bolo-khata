# Decisions log — safest defaults chosen while working autonomously

| # | Decision | Why |
|---|---|---|
| 1 | **SQLite for this build** (`data/bolo.db`), Postgres schema kept as `schema.sql` reference | Zero-ops demo reliability; integer-paise + append-only semantics preserved. "RLS" for roles is enforced in FastAPI dependencies (`require_owner`, `current_staff`, `current_customer`) — same guarantee, honest implementation. |
| 2 | **Customer auth = name + 4-digit PIN**, salted sha256 hash, first-claim-wins | No phone number collection (DPDP-lite), no SMS cost, works on any browser. Not high-security — PIN is a khata-door, not a bank vault. Wrong PIN on a claimed name → 401. |
| 3 | **PIN join always provisions a NEW khata row** (idempotent per account+shop); anonymous join falls back to name-match-or-create | Spec: a customer who joins via QR gets their own khata, not just a name-match. Anonymous joins have no identity to dedupe on, so match-or-create prevents dup-spam. Consequence: same-named rows can coexist → the resolver's ambiguity card asks which one (confirm-first, by design). |
| 4 | **Staff = seeded "Amit" (PIN in env/seeding), role `assistant`** | Demo needs one real second device. Staff can bill + stock but NOT undo, leave-mark, or shop config — enforced server-side at `/api/confirm` (peek_intent) and `/api/undo` (require_owner). |
| 5 | **Leave = dual approval**: owner voice-marks, staff must accept/dispute; append-only `leave_events` | Matches the customer-confirm trust model; both sides' states visible. |
| 6 | **Month bill = days-in-month − skips** (projects future skips) | Milkman billing convention; a "kal se skip" immediately reflects in the estimate. |
| 7 | **Ambiguous delivery product → ask which customer**, never silent-pick | "dudh band karo" with 2 doodh subscribers returns a clarification, not a guess. Same rule as fuzzy-match ties. |
| 8 | **/try sandbox: own SQLite file, recreated daily, 60 cmds/day/IP** | Judges get the full parse+ledger loop with zero credential handling and near-zero credit burn (voice relay is live but stores nothing). |
| 9 | **Proposal → stashed `db` object, not just a flag** | `/try` proposals can never write to the real ledger even if confirmed via the wrong endpoint — the stash carries its store. |
| 10 | **Noise indicator = honest proxy** | `noise_hint` = parse confidence <0.75 OR unresolved items OR detected-lang mismatch. Labeled "parse conf"/"noise — check card", never claimed as ASR confidence. |
| 11 | **No assistant-voice commands for roles** | Roles come from logins on each device. Voice can *propose* (e.g. leave-mark) but only the owner's confirm writes — same trust pattern as bills. |
| 12 | **Evon absent everywhere** | Verified 2026-11-08: Gnani console has no Evon API; FriendliAI lists it only as a paid dedicated-GPU endpoint (~$4–12/hr), not a callable API. Named nowhere except README/CODE_TOUR as "verified unused". |
| 13 | **English spoken replies fall back to Hinglish where no en template exists** | en UI exists; voice summaries/templates cover hi/te fully, en partially — logged rather than silently mixed. |
| 14 | **ngrok remains interim URL**; Vercel+Render configs committed but deployment needs owner's OAuth (in HUMAN_TASKS) | Can't log into someone's accounts autonomously. |
| 15 | **Assistant role UI**: staff logs in on the same page (Owner/Staff toggle); Shop tab + undo hidden client-side AND enforced server-side | Defense in depth — the server check is the real gate. |
| 16 | **Primary colour = deep teal `#0d5f52`** ("shop-shutter green"), warm paper `#fbf7f0` | Saffron was the other candidate but collides with the pending-amber semantic; teal stays warm against the paper bg, reads trustworthy-not-bank, and passes AA on white. Dark theme = warm charcoal `#171210`. |
| 17 | **Typography = Noto Sans + Noto Sans Devanagari + Noto Sans Telugu** via `next/font` (self-hosted woff2) | Guaranteed glyph coverage for hi/te at 1.55–1.6 line-height, tabular numerals for all money, zero runtime font requests (PWA-friendly). Google Fonts CDN rejected: offline demos must not depend on it. |
| 18 | **UI chrome = emoji + inline SVG, no icon library** | Lucide/motion libs rejected to keep the bundle tiny for slow 4G. Product icons = emoji (universal, friendly); check-draw/status = inline SVG; waveform/motion = pure CSS transform+opacity, 150–300ms. |
| 19 | **Qty editing on bill card NOT built** | Editing an item would need a reprice API — confirm writes a server-side stash, so client edits couldn't propagate honestly. Skipped rather than fake it; the owner cancels and re-speaks. |
| 20 | **Delivery calendar is read-only in UI** | `add_skips` exists only on the voice path; the polish task forbids new API surface, so tap-to-skip shows the voice hint instead. Delivered/skipped/future days still rendered per month. |
| 21 | **`?say=` demo hook kept** | Lets filming/judges drive the counter without a mic; harmless, no writes without confirm. |
| 22 | **viewport `user-scalable=no` on the counter app** | Trade-off accepted for a kiosk-style one-hand counter (accidental pinch-zoom mid-sale is worse); system font size still enlarges text, focus styles kept. |
| 23 | **v2: warm accent `#e07a2f` reserved for the ONE action** | Idle mic = teal gradient; listening = warm terracotta. Restraint rules say the accent may only mark the single most important action — on the counter that IS the mic; everywhere else it's only the active-tab dot. |
| 24 | **v2: bill/pay/result are bottom SHEETS, not inline cards** | Transactional moments belong in the thumb zone with a dimmed canvas behind; keeps the counter screen at one focal point and the CTAs under the thumb. |
| 25 | **v2: status dots over text pills** | A tiny `.dot-st` carries pending/confirmed/disputed at a glance; text pills reduced to places where the word itself is the content (/try conf, leave states). |
| 26 | **v2: undo/refresh/theme/sign-out moved into a ⋮ overflow menu** | Topbar stays one calm row (wordmark · language seg · menu); debug-looking controls removed from the hero view for the video. |
| 27 | **v2: production-build screenshots only** | The dev "N" badge and chunk-cache issues made dev-mode shots dishonest; all review shots + the hero video run on `next start`. |
| 28 | **product-v1: `users` table + per-shop token binding** | Owner/assistant tokens carry `shop_id`; every private endpoint resolves `actor → ShopDB(shop_id)`. Multi-tenant from the start — a second owner gets a second shop, never shop 1. |
| 29 | **product-v1: `ShopDB` is shop-bound via constructor** | One mechanical refactor (`self.shop_id`) instead of sprinkling shop filters — harder to leak cross-shop. Public token lookups (confirm/reminder links) stay global: tokens are unguessable UUIDs by design. |
| 30 | **product-v1: business type asked at onboarding, not in Dukaan** | Type → starter catalog + module map + tab labels at `POST /api/shop/setup`. Dukaan keeps "change type" behind confirm only — reconfiguring a live shop mid-sale is a footgun. |
| 31 | **product-v1: mic hard-stop on final transcript** | `hardStop()` kills tracks+ctx+WS the instant a final arrives; also on sheet-open / tab-hidden / logout / 20 s cap. `VoiceSession.live()` counters + `window.__bkMicLive` let the Playwright test assert 0 tracks / 0 sockets — a contract, not a vibe. |
| 32 | **product-v1: bill edits go through `/api/bill/edit` → re-stash** | Edits recompute server-side (integer paise) and produce a NEW proposal id; the audit trail keeps original transcript + edit provenance. Nothing writes without `/api/confirm` — same trust pattern. |
| 33 | **product-v1: ask-back for unresolved/ambiguous/unknown-customer** | `unresolved` + `items[].options` were already in the parser contract; the sheet now renders tappable cards (top-3 similar / ambiguity chooser / quick-create / add-customer) and speaks the question via Timbre once per proposal. |
| 34 | **product-v1: customer accounts stay name+4-digit-PIN** | No-email option deliberately kept: khata customers may not have email. `account_login` = create-on-first-use; weak-but-honest for the demo; `contact` field stores optional recovery hint. Documented as a production gap. |
| 35 | **product-v1: `?say=` env-gated at BUILD time** | `NEXT_PUBLIC_SAY_HOOK=1` compiles the hook in; without it the param does nothing. When active the transcript gets a "scripted test" label — never mistaken for a spoken take in film or review. |
| 36 | **product-v1: staff = name+PIN kept, invite-code signup added** | Existing Amit/2468 flow untouched for tests; owners now generate invite codes (`/api/staff/invite`) that bind a new staff login to their shop. |
| 37 | **deploy-verify: UPI QR lives in the pay sheet after confirm** | Found by the deployed-URL suite: `doConfirm` nulled `proposal` → the pay sheet (`paySheet && proposal`) unmounted and the QR never rendered. The QR view now keeps its own amount and the sheet stays until Done, which then shows the PAID stamp + link. |
| 38 | **deploy-verify: customer picked on the sheet must stay "dirty"** | `addNewCustomer` used to write `customer_id` back into `proposal`, which made `dirty()` false → confirm reused the stale stash and khata wrote with `customer_id NULL` (no confirm link, broken two-sided trust). Now the proposal is left untouched (only the unresolved flag clears) so `/api/bill/edit` always re-stashes with the chosen customer. |
| 39 | **deploy-verify: editable transcript rendered inside the bill sheet too** | The stage copy sat under `.sheet-back` — unreachable while the sheet was open (a tap would have dismissed the bill). A compact in-sheet transcript row + "Dobara samjho" keeps acceptance item 7 honest: transcript is editable exactly where the owner reviews the bill. |
| 40 | **deploy-verify: customer token key unified to `bk_cust`** | `/m` and `/join/[code]` read `bk_cust`; signup wrote `bk_cust_token` → new customers signed up, landed on `/m`, and were bounced to login. One key now; found by the fresh-profile customer journey on the tunnel. |
| 41 | **Deploy blocked on two one-click human actions** | Render API key is valid but repo deploys need the GitHub integration OAuth click; the `vck_…` key is Vercel AI-Gateway-scoped (403 on project create). ngrok tunnel serves the verified URL meanwhile; both are documented as human steps in HUMAN_TASKS.md. |
